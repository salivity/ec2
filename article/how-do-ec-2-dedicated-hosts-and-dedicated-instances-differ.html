How Do EC2 Dedicated Hosts and Dedicated Instances Differ?

Amazon EC2 Dedicated Hosts and Amazon EC2 Dedicated Instances both isolate your virtual machines on physical hardware dedicated to a single AWS account, eliminating shared physical infrastructure with other cloud customers. The primary distinction lies in hardware visibility, placement control, and software licensing capabilities. Dedicated Hosts provide direct visibility into physical processor sockets and cores, enabling bring-your-own-license software compliance and deterministic instance placement, whereas Dedicated Instances provide hardware isolation at the instance level without exposing underlying physical server attributes or guaranteeing host affinity across reboots.

What Is an Amazon EC2 Dedicated Instance?

An Amazon EC2 Dedicated Instance is a virtual server that runs on Virtual Private Cloud (VPC) hardware dedicated exclusively to a single customer. While your Dedicated Instances are physically isolated at the host hardware level from instances belonging to other AWS accounts, they may share the same underlying physical server with other instances in your own account—even if those other instances are not configured as Dedicated Instances.

With Dedicated Instances, AWS completely manages the underlying physical infrastructure and placement logic. You do not see which physical server hosts a given instance, nor can you query the number of physical CPU sockets or cores on the host machine. Furthermore, if you stop and restart a Dedicated Instance, AWS may launch it on a different physical server within the same Availability Zone.

Key Characteristics of Dedicated Instances

  • Hardware Isolation: Guarantees that no other AWS customer shares the physical server hosting your instance.
  • No Hardware Visibility: Physical sockets, physical cores, and host identifiers remain abstracted by the hypervisor.
  • Dynamic Placement: Stopping and starting an instance can migrate it to a new physical server.
  • Billing Model: You pay an hourly per-instance usage fee plus a flat hourly per-region fee (once per region where at least one Dedicated Instance is running), regardless of how many Dedicated Instances you launch in that region.

What Is an Amazon EC2 Dedicated Host?

An Amazon EC2 Dedicated Host is a complete physical server with EC2 instance capacity fully dedicated to your use. Unlike Dedicated Instances, a Dedicated Host grants you full visibility and control over how instances are placed on that specific physical machine. You allocate the entire host in your account first, and then launch EC2 instances directly onto it.

Because you control the specific physical host, you can inspect its hardware specifications, including the exact number of physical sockets and physical cores. You also retain host affinity: instances stopped and restarted on a Dedicated Host stay on that exact same physical server unless you explicitly move them.

Key Characteristics of Dedicated Hosts

  • Full Hardware Visibility: Exposes physical sockets, physical cores, and the unique Host ID for auditing and compliance.
  • Consistent Host Affinity: Instances remain tied to the same physical server across stop and start cycles.
  • Targeted Placement: Allows you to place instances on specific hosts or let AWS distribute them automatically across a Host Resource Group.
  • Billing Model: You pay a flat hourly rate for the entire physical host based on its instance family or size configuration, regardless of how many virtual instances you actively run on it (up to the physical capacity of the server).

Software Licensing and BYOL Considerations

The most critical operational driver for choosing an EC2 Dedicated Host over a Dedicated Instance is software licensing—specifically Bring Your Own License (BYOL) agreements for enterprise vendors such as Microsoft SQL Server, Windows Server, Oracle Database, and Red Hat Enterprise Linux.

Many legacy enterprise software licenses are bound to physical hardware metrics:

  1. Physical Core or Socket Licensing: Licenses require tracking the exact number of physical CPU sockets (\(S\)) and physical cores (\(C_{\text{phys}}\)) on the server where the workload executes.
  2. Hardware Mobility Restrictions: Vendor license terms often prohibit reassigning a license to a different physical server more than once every \(90\) days.

Dedicated Instances fail both requirements because they hide \(S\) and \(C_{\text{phys}}\) and may move to a new physical server every time the instance stops and starts. Dedicated Hosts satisfy both requirements by exposing the physical hardware topology via AWS Config and preserving exact server affinity across instance lifecycle events.

Cost Modeling and Capacity Planning

Understanding how costs scale helps determine which option is more economical for your workload size.

Dedicated Instance Cost Formula

For \(N\) running Dedicated Instances of the same type in a single region, the total hourly cost \(C_{\text{DI}}\) is:

\[C_{\text{DI}} = R_{\text{region}} + \sum_{i=1}^{N} P_{\text{instance}, i}\]

Where:

  • \(R_{\text{region}}\) is the fixed hourly per-region Dedicated fee (typically \(\$2.00\) per hour when at least one Dedicated Instance is active).
  • \(P_{\text{instance}, i}\) is the hourly rate for Dedicated Instance \(i\).

Dedicated Host Cost Formula

For \(H\) allocated Dedicated Hosts in a region, each capable of running up to \(K\) instances of a given size, the total hourly cost \(C_{\text{DH}}\) is:

\[C_{\text{DH}} = \sum_{j=1}^{H} P_{\text{host}, j}\]

Where:

  • \(P_{\text{host}, j}\) is the hourly rate for physical host \(j\), independent of whether you run \(1\) instance or \(K\) instances on it.

Utilization Efficiency

For a Dedicated Host with maximum capacity \(K\) vCPUs and active allocated instance vCPUs \(V_{\text{used}}\), the host utilization ratio \(U\) is:

\[U = \frac{V_{\text{used}}}{K}\]

When \(U \to 1\) (near \(100\%\) capacity utilization) and you are leveraging existing server-bound software licenses (avoiding license-included instance surcharges), Dedicated Hosts are substantially more cost-effective than Dedicated Instances. Conversely, if you only need to isolate a single small or medium virtual machine (\(U \ll 1\)) and do not require BYOL tracking, a Dedicated Instance avoids paying for an entire underutilized physical server.

Operational Management and Automation

Managing Dedicated Hosts used to require manual tracking of host capacities, which introduced operational overhead compared to the fire-and-forget experience of Dedicated Instances. Today, AWS simplifies Dedicated Host operations through integration with two primary services:

  • AWS License Manager: Tracks physical socket and core usage rules, prevents launching instances that violate licensing thresholds, and automates host allocation and deallocation.
  • AWS Resource Access Manager (RAM): Allows sharing Dedicated Hosts across multiple AWS accounts within an AWS Organization, making it easier to drive utilization \(U\) closer to \(1\) across business units.

When to Choose Each Option

Choose EC2 Dedicated Hosts When:

  • You need to bring existing per-socket or per-physical-core software licenses (such as Windows Server, SQL Server, or Oracle) to AWS.
  • Your regulatory or corporate compliance standards require auditing physical server serial numbers, Host IDs, and instance-to-host mappings via AWS Config.
  • You must guarantee that an instance remains on the exact same physical hardware across stop and start operations to comply with \(90\)-day license reassignment rules.
  • You can maintain high host packing utilization across predictable workloads.

Choose EC2 Dedicated Instances When:

  • You require single-tenant physical hardware isolation to satisfy a security policy or customer contract, but you do not need visibility into physical sockets or cores.
  • You are using license-included AMIs or open-source software without physical hardware licensing constraints.
  • Your workload scales elastically with variable instance sizes and counts, and you want AWS to handle physical server placement automatically without paying for idle physical host capacity.
