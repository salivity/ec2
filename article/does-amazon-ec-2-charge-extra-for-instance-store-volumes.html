Does Amazon EC2 Charge Extra for Instance Store Volumes?

No, Amazon EC2 does not charge extra per gigabyte or per IOPS for using the local instance store volumes included with an eligible instance type. The cost of the physical local storage and all input/output operations performed against those drives is completely bundled into the standard hourly or per-second compute price of the EC2 instance itself. When you launch an instance that features ephemeral local storage, you can utilize the entire capacity and push the storage hardware to its maximum throughput and IOPS limits without incurring any separate storage or provisioning fees on your AWS bill.

How Instance Store Pricing Works

An Amazon EC2 instance store provides temporary, block-level storage for your instance. Unlike Amazon Elastic Block Store (EBS), which operates over the network and is billed independently based on provisioned gigabytes, volume type, and sometimes provisioned IOPS or throughput, instance store volumes are physically attached to the host computer where the EC2 instance runs.

Because these drives—typically high-performance NVMe SSDs or SATA-based solid-state drives—are dedicated hardware components inside the underlying server, AWS includes their cost in the base rate of the instance. The total storage cost can be represented simply as:

\[\text{Total Instance Store Cost} = \$0.00 \text{ per GB} + \$0.00 \text{ per IOPS}\]

When comparing an instance family without local storage (such as the m6i family) to its counterpart that includes local NVMe storage (such as the m6id family), you will notice a slightly higher hourly compute rate for the d variant. That rate difference reflects the built-in cost of the physical SSDs attached to the host. Once the instance is running, whether you write zero bytes to the local disks or saturate them with millions of IOPS continuously, your hourly charge remains identical.

Instance Store vs. Amazon EBS Billing

Understanding the financial and architectural distinction between instance store volumes and Amazon EBS is essential for optimizing cloud storage costs.

Storage Feature Amazon EC2 Instance Store Amazon EBS
Per-GB Storage Fee Included in instance price ($0 extra) Charged per provisioned GB per month
IOPS / Throughput Fee Included in instance price ($0 extra) Charged on specific volume types (io1, io2, gp3 above baseline)
Data Persistence Ephemeral (lost on stop, hibernate, or termination) Persistent (survives instance stops and termination)
Physical Location Physically attached to the host server Network-attached block storage
Snapshot Support No native snapshot capability Supports incremental point-in-time snapshots to S3

Data Persistence and Lifecycle Considerations

While instance store volumes offer exceptional performance at no additional per-GB or per-IOPS cost, they are strictly ephemeral. Data written to an instance store volume persists only during the lifecycle of the single running instance.

  • Instance Reboot: Data on the instance store volume survives a standard guest operating system reboot or an ec2:RebootInstances API call.
  • Instance Stop or Hibernation: Data is permanently erased when the instance is stopped or hibernated, because stopping an instance deallocates it from the physical host hardware.
  • Instance Termination: Data is permanently erased when the instance is terminated.
  • Hardware Failure: If the underlying physical drive or host server fails, the data on the instance store cannot be recovered.

Because of this ephemeral nature, instance store volumes are best suited for temporary data that changes frequently, such as buffers, caches, scratch data, swap space, and temporary database transaction logs, or for data that is replicated across a fleet of instances, such as load-balanced web caches or distributed file systems.

Hidden Costs to Keep in Mind

Although the storage capacity and disk I/O operations on instance store volumes are free of extra charges, certain operational patterns involving that data can still generate standard AWS charges elsewhere:

  1. Root Volume Requirements: Most modern EC2 instances with instance store volumes still require an Amazon EBS volume to act as the root boot device. You will pay standard EBS storage rates for that root volume.
  2. Data Transfer and Replication: If you replicate data from an instance store volume to another EC2 instance located in a different Availability Zone for high availability, standard cross-AZ data transfer fees apply.
  3. Backups to Amazon S3: Because instance store volumes do not support native EBS snapshots, backing up important intermediate data requires manually copying files to Amazon S3 or another persistent store, which incurs standard S3 storage and request pricing.
